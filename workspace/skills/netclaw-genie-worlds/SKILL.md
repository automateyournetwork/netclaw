# Genie-to-Genie network worlds

Cisco pyATS Genie supplies measured facts. Google `genie-4` supplies a streamed
illustration through the documented Interactions API behind the MCP. Discover
the actual tools before using them; a skill file does not establish installation,
paid access, a generated world or membership in a Risk.

The existing **Border owns membership, enrollment, routing and task authority**.
The target is its scoped NetClaw **member**, with isolated state and agent credentials.
The member receives a backend control capability, not the Google key or raw
network snapshot. Human fact inspection and navigation use the local viewer.

## Prepare

Use `genie_world_prepare` with a saved UUID and exactly one source:
`synthetic_fixture_id: "synthetic-museum-v1"` for the first hosted qualification,
or an operator-registered `private_snapshot_ref` for local preparation. Never
pass a path, prompt, URL, key or approval boolean. A private result remains
`hosted_eligible:false` unless an operator-pinned exact projection grant matches
the selected snapshot manifest. Eligible exports stay `private_derived`; renaming
nodes or changing style does not declassify data. Backend launch pins select one
reviewed style; MCP tools cannot authorize exports or choose arbitrary text.

The local viewer provides exact scene/event review and historical fact inspection.
Preserve capture windows, source hashes, parser gaps, unavailable devices and
unqualified counters. Generated pixels never establish current network state.
Five styles may share one frozen snapshot. Honor the current exact production
scope; the owner subsequently authorized all five recorded styles after viewing
the first two. A conditional future campaign still requires its stated gates.

## Operate

Read [tools and recovery](references/tools.md) for exact arguments. Use an
existing backend-issued exact `review_ref`; the MCP has no approval-minting tool.
Before `genie_world_start`, save its UUID: `operation_id=request_id`. If the
response is lost, query that original operation. Do not invent a replacement
request, switch keys, clear a hold or infer zero cost.

The human navigates using WASD/arrows in the viewer. The provider offers streamed
movement and text events, not a persistent scene graph or per-device object API.
Local device/link buttons inspect measured facts; they do not manipulate devices.
Do not substitute Three.js, a static preview or a prepared prompt for a Google world.

For the fixed fictional lighting event, the human must mark its target visible
in the viewer. Readiness lasts 2 seconds and is consumed once. Never infer
visibility from elapsed time. Send `genie_world_event` once with a retained UUID;
pending, accepted and sent do not prove the visible change. Do not repeat the tool
call to improve the picture. One reviewed event may use Google's recommended
ten 150ms-spaced identical text impulses; a partial/uncertain burst is never replayed.
Fictional events leave measured facts unchanged.

Call `genie_world_stop`, then read status/evidence. The backend owns completion,
deadlines and connection-loss handling. A closed browser, SDK return or accepted
stop does not prove remote termination. Require a provider terminal receipt and
separately reconciled usage. Preserve unknown outcomes and their reservations.
A confirmed remote terminal receipt with missing usage retains its FULL maximum
cost reservation. The coordinator may admit distinct work within the aggregate
budget; this is not billing reconciliation and never permits replay of that ID.

## Judge the result

Require actual generated media, at least 10 seconds of navigation, a look-back,
one requested fictional event and retained baseline/navigation/event checkpoints.
Compare observed device/connection identities against the snapshot; record
missing, invented or drifting geometry and labels. Report termination, usage,
recording failures and the owner's verdict separately. The accepted Spec200
delivery is five recorded illustrations with documented visual/event limits.
Exact topology persistence and a visibly successful event in every recording
are not claimed. A future request for exact fidelity needs its own acceptance
criteria; do not silently treat these illustrations as that proof. Loop counts, offline
fixtures and tool discovery never supply live or human acceptance.

For provider capabilities and pricing, consult the official
[Genie guide](https://aistudio.google.com/docs/genie),
[model reference](https://aistudio.google.com/docs/models/genie-4) and
[price table](https://aistudio.google.com/docs/pricing#genie-4) when preparing a
new live review. Preserve existing exact authorization; do not ask again when
it still covers the proposed source, operation and allowance.
