# NetClaw 1.18.1

Spec: [168-openclaw-2026-10-compat](../../specs/168-openclaw-2026-10-compat/spec.md)

## Changes

- **Member turns name their agent.** OpenClaw 2026.10 and later refuse `--session-id`
  session creation without an owner when the home configures more than one agent. Member
  homes built by `in2n-member-home.py` copy the Border's agent entries, so on a Border
  with several agents every delegated member task failed. `gateway.run_agent_turn` now
  adds `--agent main` to a member's embedded turn when the home's config lists several
  agents and `main` is one of them, or `--agent $N2N_MEMBER_AGENT` when that is set.
  Homes with zero or one agent keep the unnamed command, because forcing `main` fails
  when the only agent has another id.
- **Failed turns say why.** When the CLI exits non-zero, the task error now includes the
  CLI's structured `error.message` (single line, at most 300 characters). Stderr is never
  included, because it can echo configuration.
- **Bootstrap files load again on older installs.** Installs from before the installer
  switched to copying `SOUL.md`, `AGENTS.md`, `IDENTITY.md`, `USER.md`, `TOOLS.md` and
  `HEARTBEAT.md` may still have symlinks into the NetClaw checkout. OpenClaw 2026.10 refuses
  symlinked bootstrap files and runs without them, logging only
  `bootstrap file is unreadable … symlink path component not allowed`. Re-running the
  installer now replaces such a link with a regular copy of its target. Regular files and
  links that point outside the checkout are left alone. Repair uses an exclusively
  created private temporary file and atomic replacement; pre-existing staging-like
  files and symlinks are preserved, and failed copies leave the original link intact.

## Upgrade and compatibility

No migration. Existing member homes, builders and units are unchanged; members pick up
the member-turn fix on restart. To repair bootstrap links without a full reinstall,
replace each workspace symlink into the checkout with a copy of its target; check with
`find ~/.openclaw/workspace -maxdepth 1 -name '*.md' -type l`. `--agent` is supported by every OpenClaw release NetClaw targets
(checked on 2026.7.1, 2026.10.6 and 2026.10.9). Set `N2N_MEMBER_AGENT` when a
multi-agent member home has no `main` agent; such a home otherwise still fails, now with
OpenClaw's reason in the task error. Hermes members are unaffected.

## Validation and known limitations

See [verification](../../specs/168-openclaw-2026-10-compat/verification.md): unit tests
for argv, override and error detail; five live members on OpenClaw 2026.10.6 completing
routed tasks under system-unit hardening. An initial 2026.10.9 run also completed all
five; the final run with corrected agent selection completed four, while visualization
hit its 600-second timeout. Installer tests cover link repair, occupied staging paths
and failure cleanup. The visualization timeout remains a follow-up, not a passing
result for that final run.

Member agents inherit the Border's workspace path when their home is copied from a
multi-agent Border. That is unchanged here and recorded as a follow-up.
