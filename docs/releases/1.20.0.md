# NetClaw 1.20.0

Spec: [181-convergence-investigation-tools](../../specs/181-convergence-investigation-tools/spec.md)

## Changes

- **`n2n_task_wait`.** After `n2n_route` or `n2n_delegate`, an agent can wait for the
  delegated task instead of checking `n2n_task_status` once, seeing `working`, and
  giving up. Each call waits up to 50 seconds and polls every 2-15 seconds. It returns
  when the task is completed, failed, cancelled, interrupted or of unknown outcome.
  - When the slice ends, it returns `still_running` with a hint to call again.
  - A task that no longer exists (HTTP 404, or a peer's `unknown`) returns `not_found`
    at once.
  - Any other failed read returns `state: error` with the HTTP status, so the caller
    can retry.

  The `n2n-federation` skill uses it when it is available. Scoped profiles that don't
  list it keep polling `n2n_task_status`.
- **Search past investigations.** `rag_search` accepts `collection="investigations"`
  (also `snapshots` or `cases`) to search every ready investigation snapshot, and
  `all` (or `*`) to search documents and snapshots together.
  - With the cross-encoder on, results are merged by its score. In passthrough mode
    they are merged by fused rank.
  - Date filters apply before the fan-out cap (`RAG_INVESTIGATION_MAX_COLLECTIONS`,
    default 50, newest first). The response reports `collections_searched` and
    `collections_skipped`.
  - Every other collection name behaves exactly as before.

Convergence's alert coordinator uses `n2n_task_wait` to wait for the member
investigating a case. Its alert receiver uses the `investigations` search to find
similar past cases.

## Upgrade and compatibility

No action needed. Existing tools, collection names and defaults are unchanged.
`n2n_task_wait` is not added to the scoped Hermes operator allowlist.

## Validation and known limitations

See [verification](../../specs/181-convergence-investigation-tools/verification.md).

- Tests: 138 across the new task-wait and investigation-search tests, the existing
  `tests/unit/test_rag_*.py`, and the related n2n tests.
- In passthrough mode, the merge orders hits by rank, so each snapshot's top hit ranks
  high.
- Date filters use the ingest time, not a snapshot's capture time.
- Not run: `tests/integration/test_rag_mcp.py`, which needs the embedding model.
