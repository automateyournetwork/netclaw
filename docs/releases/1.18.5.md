# NetClaw 1.18.5

Spec: [174-member-skill-status](../../specs/174-member-skill-status/spec.md)

## Changes

- **The Border stops routing a skill to a member that cannot load it.** Routing used only
  the member's scope, recorded at provisioning. A member's OpenClaw still withholds a
  skill whose required settings are missing, one its config disables, one not installed in
  its workspace, and one past OpenClaw's per-source skill limit. On an operator Risk, the
  pyats member could load 1 of its 18 scoped skills, and five running members could not
  load 15 between them. All of them were routable.

  After connecting, each member now asks its own OpenClaw (`openclaw skills check`) which
  scoped skills it will not load, and reports them with the reason. The Border:
  - routes such a skill to another member that can load it, or refuses at once with
    "It is in scope, but no member's runtime can load it";
  - leaves it out of the risk's advertised skills and the routable capability list;
  - logs the member, skill, reason and missing requirement names
    (`journalctl --user -u netclaw-mesh.service | grep "cannot load scoped skill"`).

## Upgrade and compatibility

No configuration change. Restart the mesh daemon and the members; each member reports when
it reconnects. A member that does not report (an older member, a Hermes member, or a
check that fails) is routed by scope exactly as before. Authorization is unchanged.

Reports carry names only, never values. Peers see neither member ids nor requirement
names.

## Validation and known limitations

See [verification](../../specs/174-member-skill-status/verification.md).

- A member runs no gateway, and `openclaw skills check` asks the configured gateway first,
  which on a member is the Border's. The member points the check at an unused local port so
  OpenClaw evaluates the member's own workspace and environment.
- The report is sent a few seconds after connecting; until then routing is as before.
- Not changed: NetClaw ships 239 workspace skills, and OpenClaw loads at most 200 per
  source by default, so the alphabetically last ~39 are never loaded on the Border.
  Raising `skills.limits.maxSkillsLoadedPerSource` interacts with OpenClaw's prompt limits
  (150 skills, 18,000 characters) and is left for a separate decision.
