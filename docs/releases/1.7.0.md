# NetClaw 1.7.0 — Hermes joins the shared HUD

Spec: [148 — Hermes HUD integration](https://github.com/automateyournetwork/netclaw/blob/v1.7.0/specs/148-hermes-hud-integration/spec.md)

Choosing Hermes now leads to a working NetClaw HUD backed by Hermes. Operators can
chat, branch an investigation in Canvas, use local Avatar and resume owned conversations
without installing or starting OpenClaw. Existing OpenClaw installations retain their
default runtime and gateway workflows.

## Changes

- **One workspace, either runtime.** Persist the selected runtime and custom home across
  fresh shells and launches. Chat, Canvas, history, Settings, configuration and available
  usage evidence follow that installation. The README explains why to choose each runtime.
- **Real Hermes execution.** The HUD API connects through an official private MCP bridge
  to a dedicated authenticated Hermes companion. The browser does not connect directly
  to the ordinary Hermes gateway. The companion uses the selected provider/model and
  pinned agent source, with isolated dependencies and reviewed tool access.
- **Tools with evidence.** The initial qualified tool is the real registered IPv4 subnet
  calculator, with its installed skill. Tool dispatch and results belong to the request;
  assistant prose alone never counts as execution proof.
- **Private, persistent investigations.** Installation identities separate conversation
  ownership, browser storage and runtime databases. Canvas branches retain the context
  captured at their branch point. Chat and local Avatar share a conversation; saved
  graph, draft, quote and file state survive the tested refresh and upgrade paths.
- **Recovery without replay.** Admission is recorded before submission. Duplicate nonces
  cannot create another run; unknown outcomes survive restarts, status can recover late
  results, and stop remains cooperative until a terminal state is observed.
- **Truthful controls and status.** Unsupported operations are rejected before dispatch.
  Missing usage stays unknown. Acceptance fixes correct the Hermes readiness badge,
  Settings rows, configured chat deadlines and known pre-admission error attribution.

## Upgrade and compatibility

For a configured Hermes installation, run from the updated NetClaw checkout:

```sh
./scripts/install.sh --runtime hermes --add "subnet-calc hermes-hud"
./scripts/netclaw hud select hermes "$HOME/.hermes"
./scripts/netclaw hud status
./scripts/netclaw hud
```

Complete `hermes setup` first; use `HERMES_HOME` or an explicit absolute home for a custom
installation. The installer can import supported repository `.env` settings while keeping
existing home values. The HUD launcher itself uses selected-home credentials and never
falls back to OpenClaw credentials. Status is observational and does not spend provider
credits. The companion neither patches nor restarts your ordinary Hermes gateway.

The HUD requires Node **24.19–24.x or 26.1+**. The installer isolates bridge/tool Python
**3.12** from companion Python **3.14**, and pins Hermes **v0.21.6** revision
`818c13be1dc4fd28987e1e881a9408224afd4535` with source and dependency checks.
Native Windows Hermes uses the Linux launcher inside WSL; native PowerShell launchers
refuse it before any OpenClaw action.

No runtime selection means OpenClaw remains the default. Preserve the selected home and
browser origin when upgrading. Legacy OpenClaw browser originals and v1 binding backups
are retained for rollback; never copy an installation identity into another home or
downgrade a v2 binding in place. Dashboard source rollback/reapply was tested; an owner
runtime downgrade was not. HUD and mobile package versions remain independent of this
repository's **1.6.2 → 1.7.0** source-version bump.

See the [setup, recovery and migration guide](https://github.com/automateyournetwork/netclaw/blob/v1.7.0/docs/HERMES-HUD.md).

## Current boundaries and next step

The protected Hermes HUD starts with IPv4 subnet calculation for `/24` through `/30`.
Installing other NetClaw MCPs does not automatically qualify them for this companion.
General network/CML tool parity, configuration APPLY, attachments, per-conversation
model/effort overrides, hosted Avatar and shared memory are unavailable in this release.
Local Avatar is supported. Auxiliary model-generated titles and automatic context
compression are disabled because they bypass the protected inference path; start a new
owned conversation when reaching the configured model's context limit.

The initial read-only tool has no eligible paused approval. Positive once/deny approval
and UI tests use controlled protocol fixtures; actual requests reject stale, foreign and
broad approvals. Optional `fwrule` was absent from the installer smoke environment and
is not newly qualified here. No live production device changes were used for acceptance.

**Spec 149 will extend n2n/iN2N federation to Hermes.** Spec 148 completes the shared HUD
connection and preserves the existing OpenClaw federation path.
