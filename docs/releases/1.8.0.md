# NetClaw 1.8.0 — Hermes NCFED and mobile

**Source version: 1.7.0 → 1.8.0. Spec149.**

Hermes can execute NCFED work as a Border or scoped member through a private,
installation-owned protected companion. Existing iN2N/eN2N transports, consent,
certificate possession, enrollment, grants and task methods are retained.

- Qualified subnet tools/skills, isolated peer chat, operator delegation and owned
  results now work through Hermes. Harness type/version is additive capability-card
  metadata, shown alongside model/capabilities; absent values remain unknown.
- Daemon/member startup, private state, interpreter records and owned stop follow
  the selected home. Remote receivers cannot acquire operator/admin/native tools.
- Durable admission and effect records prevent automatic replay. Cancellation,
  interruption, uncertain outcomes and late-result recovery are explicit.
- NetClaw Mobile **1.0.3 (6)** adds persisted request IDs, reconnect reconciliation,
  Summary Border type/model/capabilities and consistent Chat/Siri/Watch/Live Activity
  states. Voice transcripts retain voice origin. A signed archive was uploaded to
  App Store Connect on October10; Apple accepted it for processing. No public App
  Review submission or App Store release was performed.

The initial protected execution profile is read-only IPv4 subnet calculation
(`/24`–`/30`) with the installed skill. Hermes photo/video/audio attachments and
production model-guard/confinement remain unavailable. Installed MCPs do not imply
qualified execution. MSP tenant isolation is an architectural direction, not a
shipped multi-tenant security boundary.

Follow the [setup and mobile compatibility guide](../HERMES-FEDERATION.md). Read
[verification](../../specs/149-hermes-ncfed-federation/verification.md) for actual
Mac tests, runtime combinations, builds and explicit unrun platform/device work.
Spec148's prior Mac/WSL HUD qualification is historical evidence, not a fresh
spec149 WSL pass. See also [1.7.0](1.7.0.md) for the underlying Hermes HUD integration.
