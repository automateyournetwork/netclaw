# NetClaw 1.22.1

Spec: [192-skill-guardrails](../../specs/192-skill-guardrails/spec.md)

## Changes

- **When to propose the federation kill switch.** `n2n-federation` now says the agent
  proposes `n2n_kill` only for malicious or corrupted data it can see, an operator request,
  or a revoked peer that keeps connecting. A dead endpoint gets `n2n_forget_endpoint`, which
  keeps the federation; a slow peer or a general question gets neither. A proposal names
  the peer and the evidence and says restoring needs a new `n2n_consent`.
- **Only the operator sets lab mode.** `protocol-participation` Safety Rule 7: the agent
  never sets or exports `NETCLAW_LAB_MODE`, treats route mutations as production unless it is
  already `true`, and does not suggest enabling it unless asked.
- **Emergency changes are qualified.** `pyats-config-mgmt` bypasses the CR approval gate
  only when the outage, incident or exploited vulnerability is affecting production now, the
  operator has confirmed the urgency in the conversation, and the fix is a single change that
  can be rolled back. Otherwise the standard CR workflow applies. A qualifying emergency
  records the conditions and evidence in GAIT.

## Upgrade and compatibility

No migration. Skill descriptions are unchanged, so routing and skill-limit budgets are the
same. Workspace copies installed before 1.22.1 keep the old text until the skills are
redeployed (`scripts/deploy-skills.py`).

## Validation and known limitations

See [verification](../../specs/192-skill-guardrails/verification.md): catalog parity, skill
limits and the skill-related test suites. These are instructions to the agent; the MCP
servers' own CR and lab-mode gates are unchanged, and no code enforces the new rules.
