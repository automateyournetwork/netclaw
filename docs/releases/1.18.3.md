# NetClaw 1.18.3

Spec: [170-acme-renewal-credentials](../../specs/170-acme-renewal-credentials/spec.md)

## Changes

- **DNS provider credentials reach lego again.** Since 2026-09-27 the mesh launchers
  pass only `NETCLAW_`, `N2N_` and `BGP_` settings from the runtime env files to the
  daemon, which keeps unrelated secrets out of the daemon and its children. lego, which
  NetClaw runs for domain-verified certificates, reads provider variables such as
  `CLOUDFLARE_DNS_API_TOKEN` or `GODADDY_API_KEY` from its environment, so it never saw
  them: every issuance and renewal failed with "some credentials information are
  missing", and certificates expired. NetClaw now asks lego which variables the
  configured provider uses (`lego dnshelp --code <provider>`), reads those, and their
  `_FILE` forms, from `~/.openclaw/.env` and `mesh.systemd.env`, and passes them to the
  lego process only. A variable already in the daemon's environment takes precedence,
  then `mesh.systemd.env`, then `.env`.
- **Renewals finish within their timeout.** `lego renew` waits a random delay of up to
  about 8 minutes before renewing; NetClaw stops lego after 180 seconds and operator
  rotation waits for the result. Renewal now passes `--no-random-sleep`. NetClaw
  already renews only when its rotation registry says a certificate is due.

## Upgrade and compatibility

No configuration change: credentials stay where the documentation puts them. Restart
the mesh to pick up the change; the next rotation check renews a due certificate. A
certificate that has already expired renews on that check, or immediately with
`POST /n2n/certs/rotate`. The launchers' prefix filter is unchanged.

Found and not changed: generated mesh units name `mesh.systemd.env` in a quoted
`EnvironmentFile=` path that systemd ignores. The launchers read the file themselves,
so its NetClaw settings still apply; see the spec for why loading it through systemd
was left alone.

## Validation and known limitations

See [verification](../../specs/170-acme-renewal-credentials/verification.md): unit tests
with a fake lego in the real `dnshelp` layout, a Let's Encrypt staging issuance through
the new code with the real lego 4.19.2 and Cloudflare from a daemon-equivalent
environment, and the operator Risk whose certificate had expired. Providers other than
Cloudflare are covered by the generic `dnshelp` parsing, not live.
