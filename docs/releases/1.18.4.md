# NetClaw 1.18.4

Spec: [171-skill-failure-reporting](../../specs/171-skill-failure-reporting/spec.md)

## Changes

- **Delegated skills report tool failures instead of covering for them.** A delegated
  skill request asks the agent to run the skill and "return only the result". It did not
  say what to do when a tool the skill depends on is missing or fails. On an operator
  Risk, the visualization member's mind-map server failed on every call. The member
  searched the host for it for up to 1 h 43 min, then twice returned the path of a
  placeholder SVG it had written itself. The Border recorded each task as completed.

  Both request paths now include one instruction, placed before the request text: if a
  tool or command the skill needs is missing or fails, reply with that error and stop.
  Do not substitute output produced another way, such as a file the agent wrote itself.
  The two paths are Border to member, and federated peer to this claw.

## Upgrade and compatibility

No configuration change. Restart members (and the mesh, for peer requests) to pick it
up. Requests are otherwise unchanged: skill name, request text, session, time budget,
approval handling and untrusted-input marking.

The failing mind-map server itself is a separate repository,
`automateyournetwork/markmap_mcp`, which the installer clones; its fix is submitted
there.

## Validation and known limitations

See [verification](../../specs/171-skill-failure-reporting/verification.md). This is an
instruction to the model, not enforcement: NetClaw cannot check that an answer came from
the skill's tools.
