# NetClaw 1.6.1

Spec: [146-dotenv-onboarding-preservation](https://github.com/automateyournetwork/netclaw/blob/v1.6.1/specs/146-dotenv-onboarding-preservation/spec.md)

## Changes

The installer and platform setup import filled checkout `.env` settings into the selected runtime's durable environment before its wizard starts. Existing runtime values win, conflicts are reported by variable name, and no values are printed. Import preserves literal single-line assignments and writes atomically with private permissions.

Failed or unavailable onboarding now stops installation instead of reporting completion. OpenClaw onboarding and MCP deployment honor the selected state/config paths.

## Upgrade and compatibility

Existing users can run `python3 scripts/import-env.py` to preview and add `--apply` to import missing settings without reinstalling components. Add `--runtime hermes` for Hermes. Restart an already-running gateway to load newly imported settings; first-time users still complete provider/model/gateway onboarding. Existing runtime values must be edited deliberately if replacement is wanted.

Use `OPENCLAW_STATE_DIR` for custom OpenClaw state and `HERMES_HOME` for Hermes. NetClaw retains its historical installer/importer `OPENCLAW_HOME` fallback. See [setup and repair instructions](https://github.com/automateyournetwork/netclaw/blob/v1.6.1/README.md#filled-env-and-first-time-setup).

## Validation and known limitations

25 focused tests cover preview/apply, precedence, idempotence, literal values, unsafe/malformed inputs, private writes and wizard/setup orchestration. The full unit contract suite, repository declaration checks and release metadata tests pass. An isolated experiment with installed OpenClaw 2026.7.1-2 reproduces missing provider credentials before import and successful loading afterward from an unrelated working directory. See [verification](https://github.com/automateyournetwork/netclaw/blob/v1.6.1/specs/146-dotenv-onboarding-preservation/verification.md).

The reported user's command and runtime version are unknown. No real provider authentication, live Hermes wizard, daemon restart or network-device operation was performed. Import supports names declared in `.env.example` and single-line values; unknown names and obvious placeholders are skipped, and malformed/multiline input or symlink paths are refused. Inherited process variables can still take precedence. Generated launcher paths remain installer-managed.
