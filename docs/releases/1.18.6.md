# NetClaw 1.18.6 — Mobile QR enrollment in the HUD and VS Code

Generate a single-use enrollment QR directly from **HUD → Mobile** or
**VS Code → Mobile & edge**, then scan it in NetClaw Mobile. The ordinary onboarding
path no longer requires discovering and running the CLI token command.

Both interfaces use the shared enrollment service, display expiry and consumed
status, clear transient QR material, and offer explicit replacement. Mobile keeps
the same device identity through interrupted enrollment and reconnects.

## Upgrade and compatibility

- Update the Border backend to source **1.18.6** for the shared enrollment routes.
- Update the [VS Code extension](https://marketplace.visualstudio.com/items?itemName=NetClaw.netclaw)
  to **1.6.1** for editor QR generation.
- Mobile **1.0.4 (7)** contains the updated binding, pending-enrollment recovery and
  device flow. It is [submitted to Apple](https://apps.apple.com/us/app/netclaw/id6800859524)
  and **waiting for review**, with automatic release after approval. The public
  listing still serves 1.0.2 at this checkpoint. See the [release evidence](https://github.com/automateyournetwork/netclaw/blob/v1.18.6/specs/175-cloud-mobile-enrollment/release-verification.md).
- Existing enrollment keys are retained. Component updates do not automatically
  upgrade or restart an existing runtime. The phone still needs a reachable,
  correctly configured trusted WSS endpoint. The advanced CLI remains available.

## Validation and known limitations

Actual HUD and native VS Code QR images were decoded and enrolled by an iPhone
simulator across all four requested local/retained-pilot paths. The phone completed
a bounded NetBox read with a verified signed result and durable acknowledgment.
Cold launch and real background/resume recovered the same result with one attempt,
one native MCP call and one NetBox request; historical operations stayed unchanged.

Source tests cover replay, expiry, concurrent claims, uncertain replies, binding
checks and cross-device refusal. Native simulator coverage uses a test-only CPU
image decoder and Keychain P256 identity. Physical camera/Secure Enclave, Android
hardware, Windows/Linux editors and general deployment remain unqualified by
these results. [Full verification](https://github.com/automateyournetwork/netclaw/blob/v1.18.6/specs/175-cloud-mobile-enrollment/verification.md).

This owner-requested patch release publishes the Mobile enrollment usability
update. Broader cloud-roadmap deployment, identities, SSO and RBAC retain their
separate release gates. R05 has not started.
