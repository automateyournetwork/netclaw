# NetClaw 1.16.0

Specs: [164-convergence-border](../../specs/164-convergence-border/spec.md),
[165-convergence-confinement](../../specs/165-convergence-confinement/spec.md)

## Changes

OpenClaw 2026.10.9 records gateway ownership using `/proc/self/ns/pid`, which a
mount-namespaced `systemd --user` unit cannot read. Hardened embedded OpenClaw
members therefore failed every task with `GatewayLockNamespaceError`. Always-on
members can now be installed as system units (`User=` the operator) that keep the
full feature-057 confinement. A probe detects affected hosts; the posture reports
the sandbox control unavailable with remediation, production cold-start of
on-demand OpenClaw members fails fast, and the Border queries system member units
without starting them.

`scripts/border-harden.py` optionally confines the Border itself: OpenClaw Docker
sandbox for all sessions (no network, no workspace exposure, elevated exec off,
MCP tools through the sandbox gate) and Skill Workshop learning off. It is not a
default because host-script and host-network skills then run inside the sandbox.

Convergence observations can be handed to the Border through Canvas as a bounded
evidence envelope, delegated to an optional `convergence` Risk member, and are
guided to search corroborating capabilities, state the latest-100 bound, describe
records only as source -> destination and state provenance. Route refusals name
the routable specialty capabilities.

## Upgrade and compatibility

No change is required for installations on OpenClaw releases before 2026.10.9 or for
standalone NetClaw. Before upgrading a Risk with hardened always-on OpenClaw members
to 2026.10.9 or later, move each member to a system unit, as the operator user:

```bash
python3 scripts/in2n-services.py disable <member>
python3 scripts/in2n-services.py generate --system
python3 scripts/in2n-services.py enable --system
```

The commands use `sudo -n` and print the exact commands if sudo needs a password.
Roll back with `disable --system <member>` followed by the user-scope `generate`
and `enable`. On-demand (cold-start) OpenClaw members remain unsupported on affected
hosts; make them always-on or keep them on a host where the probe passes.
Border hardening is optional: `python3 scripts/border-harden.py` shows the plan and
`--apply` writes it after OpenClaw validation. Lower `agents.defaults.sandbox.prune`
on small hosts; per-session sandbox containers are retained for 24 hours by default.

## Validation and known limitations

Offline contract, HUD, catalog and spec checks pass with independent review; see the
[spec165 ledger](../../specs/165-convergence-confinement/verification.md). On a
dedicated Ubuntu 24.04 VM with OpenClaw 2026.10.9 and ollama-cloud/minimax-m3 in Risk
testing mode, 20 graded live runs across standalone, federated and denied-scope
scenarios produced 15 clean passes, 4 passes with minor unsupported inferences and 1
failure fixed by the routing hint; each scenario reached three consecutive passes and
containment held in every run. Spec164's earlier minimax-m2.7 attempts remain recorded
as failed. Production mode with DefenseClaw model-guard, cold-start members, Hermes,
macOS/WSL and other models are not qualified. Synthetic fixtures do not establish
general model accuracy.
