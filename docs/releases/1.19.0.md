# NetClaw 1.19.0

Spec: [178-convergence-setup](../../specs/178-convergence-setup/spec.md)

## Changes

- **Set up Convergence from NetClaw.** The new `convergence-setup` skill installs the
  separately operated Convergence service from a pinned release of
  [byrn-baker/convergence-platform](https://github.com/byrn-baker/convergence-platform)
  (`v0.1.2`). It discovers what it can, asks for the rest (secrets stay in private
  files), shows the plan and waits for approval, then follows the release's own
  procedures: a Docker trial, an existing K3s cluster with Helm or Argo CD, or a new K3s
  cluster on Proxmox VE. Proxmox changes stay inside the VMID range and name prefix you
  approve. The skill carries no code; the helpers are versioned with the service.
  It also offers the service's optional procedure that lets NetClaw investigate
  admitted alert cases with a restricted agent; that wiring ships with Convergence,
  is off by default and is not part of NetClaw.
- **VM Security findings (proposal 176).** `convergence_vm_security` and a VM Security
  section in the HUD's Convergence view show advisory findings from a hypervisor-side
  observer: possible port scanning, possible network sweep and protected network contact,
  with per-source coverage. Findings are for review, never a verdict. The section loads
  only when opened, and the service's labelled synthetic source lets you try it without
  a hypervisor.
- Convergence docs, the catalog and the integration test now pin the convergence-platform
  release instead of a fork commit.

## Upgrade and compatibility

No new setting: VM Security uses the existing `convergence-read` endpoint, site and viewer
key. It needs convergence-platform `v0.1.1` or later; an older service makes the VM
Security section report "incompatible" while flow evidence keeps working. Reinstall or
update the `convergence-read` component to pick up the new tool.

## Validation and known limitations

See [verification](../../specs/178-convergence-setup/verification.md).

- Linux only, as for spec 162. Proxmox VE is the only live VM Security source.
- Exercised live: the Docker trial, and a new three-server K3s cluster on one Proxmox VE
  node with Convergence deployed by Argo CD. The plain Helm install on an existing
  cluster is covered by the service's tests only, and macOS/WSL2 are untested.
