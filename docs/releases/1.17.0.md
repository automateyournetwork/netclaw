# NetClaw 1.17.0

Spec: [166-coldstart-system-members](../../specs/166-coldstart-system-members/spec.md)

## Changes

Release 1.16.0 moved always-on members to system units because OpenClaw 2026.10.9
cannot run an embedded member inside a mount-namespaced `systemd --user` unit, but
on-demand (cold-start) members still used user-scope confinement and could not run
confined on affected hosts. This release adds a hardened system template,
`netclaw-coldmember@.service`, and a polkit rule installed once by the operator.
The Border, running as that operator, starts and stops only those instances without
sudo. Each instance runs as the operator with the same confinement as system member
units. A launcher resolves the instance name to a registered, local, on-demand member
from the Risk registry (read-only) and runs only that member's launch command; unknown
names run nothing. A reserved `probe` instance verifies authorization.

## Upgrade and compatibility

Nothing changes unless the operator installs the template. On hosts where OpenClaw
members cannot run under user-scope confinement and on-demand members are used:

```bash
python3 scripts/in2n-services.py coldstart install   # sudo -n; prints commands otherwise
python3 scripts/in2n-services.py coldstart status     # template + authorization probe
```

Remove with `coldstart remove`. The rule authorizes only the installing user, only
`org.freedesktop.systemd1.manage-units`, only `netclaw-coldmember@<instance>.service`
and only start/stop, and only while the template file exists. On systemd 257 and
later polkit also authorizes transient units by the requested name; the template's
unit file is what prevents a same-named transient unit (for example with `User=root`),
so the rule re-checks it on every request, is installed only after the template and
removed before it. Use `coldstart remove` rather than deleting the template by hand.
Requires polkit with JavaScript rules (polkit 0.106+; Ubuntu 24.04 ships 124).
Changing `N2N_RISK_MODE` after installation requires reinstalling, as for member units.

## Validation and known limitations

Offline tests cover the template, rule text, launcher, install/remove/status and
posture/cold-start integration. On a dedicated Ubuntu 24.04 VM (systemd 255,
polkitd 124, OpenClaw 2026.10.9) the real polkit daemon allowed start/stop of the
template from the Border's `systemd --user` context and refused other verbs, units
and templates; a cold-started member ran a delegated embedded OpenClaw task under full
hardening, idle-exited cleanly and restarted; removal reverted the posture. See the
[ledger](../../specs/166-coldstart-system-members/verification.md). Production-mode
delegation end to end requires the DefenseClaw model guard and was not exercised
live; Hermes, macOS and WSL are not affected or not qualified.
