# NetClaw 1.18.2

Spec: [169-task-timeout-error](../../specs/169-task-timeout-error/spec.md)

## Changes

- **Timed-out member turns say so.** A member's embedded turn (`openclaw agent --local`)
  is bounded by its time budget. When the budget ran out, the process was killed and the
  task failed with an empty error, so the Border's `GET /n2n/tasks/<id>` showed `failed`
  with no reason and the member logged "Task <id> failed: " with nothing after it. The
  error now reads "agent turn for session '<session>' timed out after <n>s", matching
  the wording the gateway path already used.
- **No empty task errors.** If any delegated task worker fails with an exception that has
  no message, the task records the exception's type name (for example `TimeoutError`)
  instead of an empty string. Errors that have a message are unchanged.

## Upgrade and compatibility

No migration. Members pick up the change on restart. Time budgets, task states
(`failed` vs `outcome_unknown`), cancellation and the gateway path are unchanged.

## Validation and known limitations

See [verification](../../specs/169-task-timeout-error/verification.md): regression tests
for a hung CLI and a message-less worker failure (both fail on 1.18.1), and a check with
the real OpenClaw 2026.10.9 CLI. Not covered: a routed task reaching a member's full
600-second budget on a live Risk; the path exercised is the same `run_agent_turn` code.
