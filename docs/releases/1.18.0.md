# NetClaw 1.18.0

Spec: [162-netconverterai](../../specs/162-netconverterai/spec.md). Coordinated VS Code extension: **1.5.0**.

## Changes

NetConverter is an optional migration specialist in NetClaw. Choose hosted read-only access or an operator-installed licensed Terminal in VS Code or terminal setup. The guard discovers current account capabilities and requires separate native approval of the exact files before each hosted submission. Unknown outcomes cannot be automatically replayed. Converted output remains a reviewable candidate.

Private pyATS collection and candidate application retain the original tool identities and policy checks. Terminal Intent binds the candidate, endpoint, original baseline and rollback evidence to a one-use Local/Lab APPLY grant. A dedicated OpenClaw Risk member owns the converter credential and workspace; the Border delegates without receiving that credential.

Minor fixes discovered in real qualification address native HUD reference assets and gateway authentication, multi-turn pyATS session lifetime, original-baseline verification and Risk endpoint registration order. Upstream Convergence, confinement, cold-start and production-mode work through **1.17.1** is retained. Both independently named Spec162 directories are preserved; use their full paths when referring to them.

## Upgrade and compatibility

The extension requires source **1.18.0** for this combined feature release. Extension updates do not upgrade existing runtime homes. Install NetConverter only in the selected claw, configure its own account, and install/accept the licensed Terminal separately when using local-Terminal mode. No installation step uploads a configuration. Existing running owner and qualification environments are unchanged by this source release.

The earlier NetConverter 1.15.0–1.15.5 branch milestones were unpublished. They are retained as development history; upstream's published 1.15.0 Convergence notes remain authoritative for that version.

## Validation and known limitations

All **44 scoped Spec162 tasks**, five implementation loops and three additional live qualification loops are complete. Actual approved synthetic IOS-XE → Junos SET → IOS-XE conversions, bounded Batfish analysis, a protected IOS-XE target/peer rehearsal, and native Border/member authenticated discovery are recorded in [verification](../../specs/162-netconverterai/verification.md). The CML trial observed OSPF FULL, reciprocal routes, positive traffic, negative controls and preserved management. Owner routers were restored.

Junos appliance acceptance, universal vendor support and production artifact grants are not qualified. The final Mac Risk installer used owner-requested simulated review inputs with real effects and agents. Native Windows/WSL and Hermes NetConverter member qualification remain open boundaries. See [release verification](../../specs/162-netconverterai/release-verification.md) for the final merge, tests and package evidence.
