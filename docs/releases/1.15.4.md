# NetClaw 1.15.4 — NetConverter Risk member, unpublished

The shared native setup catalog now includes a dedicated **NetConverter** member
profile for OpenClaw. Both VS Code and terminal setup can select it. A Border uses
n2n/protocol routing while the member receives the NetConverter guard and skill,
its own integration state and its own selected credentials. The Border cannot
select the domain component. Hosted file approval remains separate per submission.

The missing profile was exposed by the owner's requested Border-plus-one-member
installer test. A regression first failed with `unsupported_member_profile`, then
passed with member settings and state confined to its home. The owner requested
simulated review input with actual installation and federation checks; that is
recorded as an automated test, never as a fresh human UI approval.

[Spec162 evidence](../../specs/162-netconverterai/verification.md) retains the actual
IOS-XE appliance pass and current installation results. The earlier Focused native
plan is superseded. Extension source remains 1.5.0; it reads this source catalog.
