# NetClaw 1.25.0

Spec: [198-percepxion-oob-skill-refresh](../../specs/198-percepxion-oob-skill-refresh/spec.md)

## Changes

The `percepxion-oob` skill is rewritten around a short `SKILL.md` (routing, rules and a workflow index) with setup, workflow and source-of-truth detail in `references/`. Tool parameters now match the Lantronix servers NetClaw installs, including corrected calls for syslog upload, the device access log and job search. Two new workflows read NetBox or Nautobot: W9 finds a managed device's console path by its source-of-truth name and confirms it in Percepxion before returning it, and W10 runs the console coverage gate from the Lantronix NetBox plugin or Nautobot SSoT app before a change. README, TOOLS.md and the component catalog now give the Percepxion server's 38 tools.

## Upgrade and compatibility

No migration. The skill name, required environment variables and MCP servers are unchanged. W9 and W10 use the existing `netbox-mcp` and `nautobot-mcp` servers; they need console cabling in NetBox or Nautobot, normally kept current by the `netbox-lantronix` plugin, the `nautobot-app-ssot-lantronix` app or the `lantronix.oob` NetBox playbook. Deployments that copied the old skill by hand should copy the whole `percepxion-oob` directory, including `references/`.

## Validation and known limitations

Catalog, reconciliation, skill-limit, spec and release checks pass. The W9 NetBox and Nautobot queries were run against live instances; W10 and the Percepxion steps were checked against the server and plugin sources, not run end to end in NetClaw. See the [verification record](../../specs/198-percepxion-oob-skill-refresh/verification.md).
