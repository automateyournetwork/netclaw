# R02 engineering qualification sequence

This is a maintainer acceptance outline, not a deployment or release guide.

1. Review the spec, frozen contracts, parity matrix, tasks and analysis findings.
2. Run focused fixture tests in the isolated Python/Node runtimes. These are
   synthetic evidence. Confirm legacy profiles retain their behavior.
3. Review the exact local activation packet. Use fresh private homes, pinned
   official runtime/guard artifacts and broker-owned MCP credentials.
4. Create a one-use owner ticket through the trusted local shell. Log in through
   the browser, prepare `show version`, review member/model/device/arguments and
   approve once.
5. Correlate the actual MCP invocation, tool result, signed receipt, durable ACK
   and GAIT record.
6. Exercise scope/tamper/bypass refusals and lost-ACK recovery without another
   effect. Record actual invocation counts, not just equal answer text.
7. Record platform/provider qualification limits and present the R02 evidence
   for human acceptance.

This outline authorizes no cloud resources, release changes or R03 execution.
