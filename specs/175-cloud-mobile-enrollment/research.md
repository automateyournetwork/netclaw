# R04b research decisions

1. **Decision**: retain the four-field enrollment QR, additive `installation_id` and `ws_path`, default local path `/`, cloud `/mobile/ws`. **Rationale**: existing `enrollment_qr_payload.dart` and `EdgeClient` already implement challenge, enrollment and hello but cannot multiplex cloud443. **Alternative rejected**: manual cloud wizard/user ticket; violates owner intent and bypasses existing scanner.
2. **Decision**: existing native authority issues edge-only tokens with a durable client nonce,120second expiry and one outstanding offer. **Rationale**: current raw member token is not device scoped. Repeated nonce must never mint twice. **Alternative rejected**: expose daemon token/admin route publicly.
3. **Decision**: native qrcode returns bounded boolean matrix; HUD/VSCode render locally with4module margin. **Rationale**: dependency exists, avoids new QR package/third-party service; matrix is secret-equivalent. **Alternative rejected**: log/share raw payload or external QR generator.
4. **Decision**: protected operations use authenticated WSS and native device authority, reusing exact existing backend reviews, signatures and ACK. **Rationale**: legacy edge Ask/approval IDs differ from protected operation semantics. **Alternative rejected**: new HTTP user session/token flow or enabling legacy Ask.
5. **Decision**: persist pending member/key fingerprint/endpoint/installation before enroll, never persist token; after uncertainty use hello only. **Rationale**: currently a lost enroll reply can discard the returned fingerprint and encourage replay. Compute public SPKI fingerprint locally and verify returned identity.
6. **Decision**: native simulator harness with actual QR decoding and test-only Keychain P256 identity, importing production screen/client. **Evidence**: installed mobile_scanner7.4.0 iOS implementation explicitly refuses analyzeImage in Simulator; production identity plugin requires SecureEnclave. **Alternative rejected**: claim unit payload injection qualifies camera hardware, or weaken physical production key storage.
7. **Decision**: capability-route protected enrollment before legacy HomeShell/headless entry. **Rationale**: those paths initialize Ask/capture/watch/push unconditionally. Legacy local flow remains separately tested.
8. **Decision**: retain/patch the usable owner pilot after fresh baseline, and keep temporary local/simulator state separate. **Rationale**: R04a taught that retiring the intended deployment does not deliver the requested product. No new cloud resources by default; old spent plans never replayed.

Design is based on inspected repository and installed native tool source, not an external service claim.
