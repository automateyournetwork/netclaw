# R06 Maintainer Qualification

This is an internal evidence procedure, not a public cloud deployment guide.

1. Read spec/plan/contracts/current private state. Preserve owner deployments and independent R05 teardown. Never replay old packets.
2. Focused selected-home MCP, strict triangle, ordinary cloud, peer-chat and provenance tests; affected full regressions afterward.
3. Build fresh source closures/homes/narrow gateway profiles. Prepare exact foundation/activation/teardown plans with current cost and finite lifetime.
4. Under actual scoped activation authorization, establish local→A/local→B/A→B. Record reachability, identity, consent and capability separately.
5. All six directed cases: permitted inventory, two-turn contextual chat, real subnet native tool and async skill/result. Correlate actual provider/native evidence.
6. Missing/one-sided/revoked consent; wrong identity/pin/binding; hidden capability/budget/member/admin/transit refusals. Zero unauthorized effects.
7. Actual browser, VS Code and iPhone simulator; selected identity/peer attribution and original-result cold/reconnect recovery without additional effects.
8. Owned peer loss/lost response: preserve original IDs/unknowns and recover read-only. This does not close the later R07 gate.
9. Export private evidence, preserve intended usable delivery, retire disposable resources and verify residue inventory.
10. Coherence, verification matrix, memory and GAIT. Do not claim100% while required actual acceptance/lifecycle work remains open.
