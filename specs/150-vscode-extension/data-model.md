# Data model — NetClaw VS Code management contract 1

Design only. Records belong to one installation; display names and client labels never identify a principal. Backend SQLite is authoritative for admission, grants, proposals and ownership. Editor storage holds nonsecret references and drafts only. All timestamps are UTC with explicit source time; unknown is distinct from zero or false.

| ConnectionProfile | profile UUID, label, transport local/SSH, explicit launcher, SSH alias if used, extension-host context, verified host fingerprint, installation UUID, principal reference | Owner-selected absolute path; no workspace command or embedded credential. Non-synced host-scoped editor storage. WSL distribution plus backend UUID must match after restart. |
| InstallationSnapshot | UUID, management contract major/minor, source version, harness kind/version/root reference, effective role, config revision, capability observations, observed time | A host can have several installations. ## State transitions

- Connection: disconnected → connecting → verified-ready / verified-partial / incompatible / denied / unavailable. Identity drift forces disconnect and fresh operator review. Cached data becomes stale; it never enables mutations.
- Operation: admitted → preparing → waiting-approval → running → succeeded / failed / rolled-back / rollback-failed. Read-only work can move directly from admitted to running. Process/transport loss yields interrupted or unknown until authoritative reconciliation; read-only status cannot requeue it.
- Cancellation: a request records cancellation-requested; only authoritative runtime confirmation produces cancelled. Already-completed results remain completed. Revocation prevents new dispatch immediately and requests cancellation for owned active work where supported, without asserting rollback or termination succeeded.
- Proposal: proposed → preparing → pending-approval → ready → executing → verified / failed / rolled-back / rollback-failed. It may become denied, withdrawn, stale or expired before execution. No assistant transition to ready/executing; a human initiation and independently verified authority are required.
- Configuration: drafted → validated → reviewed → approved-as-required → written → pending-restart → verified, with explicit conflict/failure/rollback branches. Lost response never means failed/no change.

## Retention and concurrency

Journal writes use process-safe SQLite transactions, unique admission constraints and per-target locks with bounded leases. Only installation-owned workers may renew execution leases. The canonical digest includes target and operation inputs but secret replacements use ephemeral keyed digests; no reusable secret oracle. Locks span HUD, CLI and extension paths for shared managed resources.

Persist terminal outcomes and admission tombstones at least as long as any supported client retry window; expired nonces are rejected rather than treated as new requests. Initial contract uses a 24-hour submission window and 30-day deduplication tombstones. Evidence retention may vary, but a missing artifact is explicit and cannot erase admission or mint authority. No automatic destructive audit cleanup is introduced. Transaction migrations have backups, interruption recovery and a documented downgrade refusal when safe rollback is impossible.
