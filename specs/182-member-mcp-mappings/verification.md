## Tests

- `tests/n2n/test_member_mcp_mappings_182.py` (50 tests). Fixture Borders with installed
  entries are generated by running `scripts/install-mcp-config.py` for every catalog component,
  so entries carry exactly what the installer writes (`native_entry` output, recorded
  interpreters, `NETCLAW_RUNTIME_ROOT`/`NETCLAW_RUNTIME_ENV`).
  - Mappings: every server named in `MCP_SERVERS` is registered in `config/openclaw.json`,
    except `ipfabric-mcp`, accepted only because `scripts/ipfabric-enable.sh` names it; every
    key is a `PROFILE_MATCHERS` profile, apart from `splunk` and `gnmi`; corrected mappings
    (pyats, cml, nautobot, github not gitlab, netbox, catalyst-center, fortimanager); eve-ng,
    containerlab, aci, f5, ise, infoblox and asa stay unmapped, checkpoint keeps its five; each
    profile keeps exactly the catalog-bound servers apart from the recorded exceptions.
  - Scoping: `scoped_mcp_servers` keeps the mapped servers plus `memory-mcp` and skips ones the
    Border lacks; `in2n-member-home.py --member cml` writes exactly `cml-mcp` and `memory-mcp`.
  - Runtime paths: the installed entries for pyats, netbox, nmap and drawio point at the
    Border's `.env`. For every profile, no kept entry in a scoped member config contains the
    Border's `.env` or runtime root, and a rewritten entry names `<member>/.env` and
    `<member>/python-runtimes`, and the Border's map is left unmodified. A `component-launch.py` entry
    without those keys gets them. `in2n-member-home.py` run on the installed Border for pyats,
    netbox and viz writes none of the Border's paths, gives pyats the Border's `pyats-venv`,
    copies the netbox record (0600, directory 0700), and `--member-env` sets the named file.
  - Member env file (round 2): `in2n-member-home.py --member pyats` with no `<home>/.env`, with
    a missing `--member-env`, or with a symlinked one exits non-zero, names `pyats-mcp`, the
    path and `--member-env`, prints no traceback and writes no `openclaw.json`; a cml member
    (no component-launched server) needs no file. `in2n-migrate.py` prints the pyats member's
    command ending `--member-env <staging>/members/pyats/.env`, the runbook contains it, and
    running that exact command provisions a home whose `pyats-mcp` loads the staged slice.
  - Border `.env` and home (round 3): `--member-env` naming the Border's `.env` directly, through a
    `..` path, or through a hard link is refused ("the Border's .env"); `--home` at the Border's
    home, with or without `--member-env`, and a `..` path to it, are refused ("is the Border's
    home"); the Border's `openclaw.json` is unchanged. A directory `--member-env` is refused; a
    relative one is written as the absolute path. The migrate command test runs with the staging
    directory `stage` and `st age$x`: the printed command splits with `shlex.split`, its last
    arguments are `--member-env` and the exact staged path, and running it provisions the member.
  - `PYATS_VENV` (round 2): an entry `{'args': [.../component-launch.py, 'pyats']}` with no
    runtime root gets the Border's `pyats-venv` from `border_root`, and `main()` derives it from
    the Border config's directory. A symlinked record target is refused and its target left
    unchanged.
  - Change root (round 2): `component-launch.resolve('pyats')` with a member's rewritten env
    sets `NETCLAW_CHANGE_ROOT=<member>/netclaw-changes`, loads the member's `.env` and not the
    Border's, and keeps the Border's `PYATS_VENV`; `PrivateMigration.claim` in that vault raises
    `Refused`.
  - Env slices, against the template and the installed entries: every allowed `${NAME}` a
    profile's kept servers reference is in its slice; every slice key is a prefix key or a
    kept-server name; no slice holds a `SERVICENOW_` or comms key. Previously missing names are
    present (aap, catalyst-center, terraform, claroty `NETCLAW_LAB_MODE`, nautobot `ITSM_*`,
    viz, sdwan, gns3, splunk, gnmi). claroty, fortimanager and gnmi do not get `SERVICENOW_*`
    although their servers reference it; an operator `ENV_PREFIXES` grant restores it; comms
    keys from comms.json (`EMAIL_PASSWORD`) and comms prefixes are never derived; a server not
    kept contributes nothing.
  - Reference parsing: command, args, url, headers, env values and `${NAME:-x}`/`${NAME-x}`;
    nested `${A:-${B}}` yields both; dict keys are not references; `$${A}` still yields `A` (no
    escape, as `mcp_environment.BARE`); bare `$NAME`, `$$`, `${` and `${1BAD}` yield nothing.
    Without a template only the prefixes apply.
  - Migrate: on an installed Border, staged catalyst-center, claroty and pyats `.env` files
    hold their prefix and server names (`CATALYST_CENTER_*`, `CLAROTY_API_TOKEN`,
    `NETCLAW_LAB_MODE`, `PYATS_*`, `MEMORY_DATA_DIR`), none of Slack, GitLab or ServiceNow, and no
