# Qualification guide: Hermes NCFED federation

This document defines the implementation acceptance procedure; commands or evidence are not claimed to exist or pass until recorded in verification.md.

1. Run focused Python contracts for selected runtime/card, scoped execution/approval, task uncertainty and member provisioning. Run existing federation tests to catch grant/transport/knowledge/replication/edge regressions.
2. Install the existing Hermes protected-runtime component into isolated temporary homes, using the spec148 pinned source/interpreters. Preserve owner runtime/home files and services. Start separate federation namespaces with test-only keys and unused ports.
3. Use the real Hermes agent with controlled local provider and real installed subnet MCP. Prove no OpenClaw executable/config/service exists in all-Hermes fixtures. Verify enrollment, inventory, route, tool and async skill result through real local NCFED channels.
4. Repeat the same internal journey for H/H,H/O,O/H,O/O, identifying which runtime executed. External H↔H/H↔O must exchange cards, run two contextual peer turns and independent same-peer conversations, execute tool/skill and retrieve results. Controlled provider evidence is labeled; hosted provider evidence is a separate row.
5. Exercise revoked/replaced grants, expired/reused approvals, forged origin/permit/target, cross-owner task lookup, missing scope and missing enforcement. There must be zero forbidden handler invocations.
6. Kill only test-owned bridge/companion/member/daemon processes before/after admission and result persistence. Verify no replay, durable uncertainty, cancellation truthfulness, bounded deadlines and retained unresolved evidence.
7. Test custom-home selection from another cwd, populated-home repeat install, companion/member locks, port conflict, owned stop and state rollback/preservation. Record file hashes without storing secrets.
8. Run HUD Node tests and build, then real browser Chat/Canvas/local Avatar and federation/harness/status journeys where available. Existing non-federation restrictions and browser ownership must remain.
9. Run catalog/inventory/spec/reconciliation/security/release checks appropriate to changed artifacts. Prepare the milestone article and publish it under the owner’s explicit later authorization; include both PRs and all five images. Public App Review/release remains excluded.
10. Record per-host/runtime/role/control evidence in verification.md. Mac testing does not establish Linux/WSL production confinement. Record unavailable hosts as unverified, leaving corresponding acceptance tasks open rather than inventing a pass.

Expected acceptance matrix: four internal runtime pairs; H/H and H/O external bidirectional plus O/O regression; legacy/unknown/stale cards; authenticated owner isolation; stopped/unknown task states; zero owner-state modification. A card, mock answer or successful handshake alone never satisfies execution acceptance.
