## Clarified scope

The owner selected Hermes Borders **and** members, including mixed and all-Hermes Risks. Required internal runtime pairs are H/H, H/O, O/H and the existing O/O regression pair. Required external pairs are H↔H and H↔O in both requester/responder directions, with existing O↔O regression coverage.

The owner also requested harness identity alongside model/tools in the capability card. A candidate additive shape is `"harness": {"type": "hermes", "version": "0.21.6"}`; this is a planning example using spec 148's qualified version, not an implemented field or a statement about a live node. Existing `llm`, `mcp_servers`, `skills` and `posture` remain separate. The technical contract must define safe parsing, version unavailability, old/new-reader compatibility and freshness. External peers see the advertising Border's harness, not a per-member topology dump. Claimed remote harness metadata is informational, not attestation of a software build or permission to execute.

## Evidence limits and planning follow-up

- No live federation session, runtime/provider request, configuration application, service restart or device operation was performed. The specific reported deployment/version/error was not supplied. Source evidence nevertheless demonstrates several independent OpenClaw dependencies.
- Spec 148's exact Hermes source/version and protected companion are the starting evidence, not proof that all needed federation operations can safely use that path unchanged. Planning must verify the runtime contract, request ownership, scoped tool execution, skill context, trust propagation, usage and cancellation semantics.
- Inventory and directly calling an MCP tool do not prove that a Hermes agent can discover and invoke it. End-to-end qualification must separately demonstrate agent → federation → executor → result → operator.
- The production member-confinement model is host-dependent. [N2N-RISK.md](../../docs/N2N-RISK.md) documents host-level confinement and why OpenShell containers were rejected for live-infrastructure members. Some older module comments/README descriptions still say OpenShell; validate executable controls rather than treating those comments as the implementation contract.
- Assess readiness and refusal cases as well as successful execution. Preserve existing consent, trust, grants, budgets, task ownership, revocation, production change controls and GAIT semantics. No assumption is made that prompt policy alone enforces them.
- Planning must assign a qualification/disposition to the relevant existing federation operations, including shared knowledge, replication and edge paths; avoid a blanket Hermes-parity claim from a single passing subnet call.
- Startup `pyats_list_devices` failed the existing testbed schema check (`connections.defaults.arguments` unsupported). MemPalace's installed component binding was unavailable. No device-state or long-term-memory claim follows from those failures.
- This is the specify/clarify evidence baseline. Technical research, design contracts, task breakdown and cross-artifact analysis remain subsequent SDD stages.
